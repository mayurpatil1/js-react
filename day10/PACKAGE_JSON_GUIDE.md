# package.json, field by field

Compared throughout to Maven's `pom.xml` / Gradle's `build.gradle`, since
you already know what those do.

```json
{
  "name": "day10-npm-basics",
  "version": "1.0.0",
  "description": "...",
  "main": "lesson.js",
  "scripts": {
    "start": "node lesson.js",
    "greet": "node -e \"console.log('hi')\""
  },
  "dependencies": {},
  "devDependencies": {}
}
```

- **name / version** — same idea as `<artifactId>` / `<version>` in Maven.
  `version` follows semver (`MAJOR.MINOR.PATCH`) — same convention Java
  libraries mostly follow too.

- **main** — the entry-point file if someone `require()`s your whole
  package (mostly relevant for published libraries, not app code).

- **scripts** — this is the big one. Each key becomes a runnable command:
  `npm run start` runs `node lesson.js`. This is npm's equivalent of Maven
  plugin goals (`mvn spring-boot:run`) or Gradle tasks (`./gradlew bootRun`).
  Two scripts have shorthand: `npm start` and `npm test` work without the
  word "run" — everything else needs `npm run <name>`. React/Vite projects
  always define `dev`, `build`, and `preview` scripts here.

- **dependencies** — packages your app needs AT RUNTIME. Direct equivalent
  of Maven's default (`compile`) scope dependencies.

- **devDependencies** — packages only needed while developing/building
  (test runners, bundlers, linters) — never shipped to production. Direct
  equivalent of Maven's `test` scope, roughly.

- **package-lock.json** (not shown above, but npm generates it automatically)
  — pins the EXACT version of every dependency and sub-dependency that got
  installed, so everyone on the team gets identical versions. Equivalent
  job to Maven's dependency resolution being locked by an exact `pom.xml`,
  though Maven doesn't generate a separate lock file the same way — closer
  in spirit to Gradle's dependency locking feature. Always commit this file.

- **node_modules/** — where the actual downloaded package code lives, the
  equivalent of your local Maven `.m2` repository, except it's per-project
  instead of shared globally. This folder is never committed to git — it's
  regenerated by running `npm install`, which reads package.json +
  package-lock.json and downloads everything listed.

## Semantic versioning symbols you'll see in dependencies

- `"react": "18.2.0"` — exact version only.
- `"react": "^18.2.0"` — allow minor/patch updates (18.x.x), not 19.
  This is the default npm uses and what you'll see most often.
- `"react": "~18.2.0"` — allow only patch updates (18.2.x).

## Why this matters for Vite/React projects

Every React project you'll ever `npm install` into has this exact same
file at its root, with `dev`/`build`/`preview` scripts already wired up by
Vite. Once VITE_SETUP.md's commands are run, this is
the first file worth opening in a new project to see what's actually there.
